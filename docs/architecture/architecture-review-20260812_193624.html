Problem

The config seam is the shallowest point in the dependency graph. Import-time env-var reads create invisible coupling. Module-level state in standardization makes the API asymmetric: standardization uses cached stats while destandardization re-reads YAML on every call. Silent mismatch risk when DLAMP_EXP_CODE does not match the model version.

Solution

Replace import-time globals with an explicit RuntimeConfig object constructed once and passed to consumers. Standardizer class loads stats in init and exposes both directions through one shared seam. Env-var mismatch validated eagerly instead of silently applying wrong standardization.

Wins

  • locality: bugs in config propagation concentrate in one seaming module
  • leverage: one Standardizer interface across 4 call sites
  • interface shrinks: no implicit import-time state
  • testability: Standardizer testable with fake config and in-memory stats

Problem

The ONNX and ckpt inference classes duplicate the entire auto-regressive loop, boundary swapping, and post-processing. Only the model-call differs. The deletion test: removing one leaves an if-else on the backend — they are already shallow enough to be one class.

Solution

Wins

  • leverage: one loop tested against 3 backends (onnx, ckpt, fake)
  • interface shrinks: one infer method replaces two classes
  • testability: auto-regressive loop testable without GPU or ONNX runtime

Problem

Three independent naming systems coexist: DataType.nc_key for metadata, DataCompose.combined_key for data reading, and a hardcoded key_map dict for writing. Unit conversions for Qt (kg/kg to g/kg) appear in both file_util.py and forecast_saver.py. A variable that reads correctly can silently write to the wrong NetCDF key.

Solution

Introduce a VariableRegistry as the single naming seam. All read, write, and standardization code resolves variable names through it. Move unit conversions to a UnitConverter registered per variable, applied at the read/write boundary in one place.

Wins

  • locality: naming and units defined in one registry not three files
  • leverage: one registry consumed by read, write, stats, and metadata
  • interface shrinks: key_map dict deleted entirely
  • data integrity: no silent key mismatches between read and write

  • leverage: render pipeline tested with fake renderers
  • testability: colormap logic testable without matplotlib figures

Top recommendation

Start with Collapse the Config Seam. It is the deepest root cause: the shallowest module in the dependency graph, imported by nearly every file. Import-time side effects, module-level state, and the asymmetric standardization API propagate through the entire codebase. Fixing this one seam would make the backend adapter (Candidate 2) and trainer builder (Candidate 4) candidates easier to test, because both depend on the config being explicit and injectable.

After the config seam, tackle Unify the Variable Naming Seam (Strong) to address the data-integrity risk, then Unify the Backend Adapter Seam to cut the duplicated inference loops.
